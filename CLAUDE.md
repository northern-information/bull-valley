# Bull Valley Shadow Wars

An extraction adventure RPG set in a hauntological Bull Valley, Illinois. 3D first-person in the browser, WASD + mouse, PS1 aesthetic. The engine was ported from forgotten-industries' ground-survey spike (provenance sha in the first commit); the spike's branding is gone — this is Bull Valley Shadow Wars, and a session of play is a **raid**, never a "run".

## Commands

- `npm run dev` — Vite dev server on port 5174. The Cloudflare Worker and its Durable Object run beside it in workerd (`@cloudflare/vite-plugin`), so this is the whole stack: open two windows and they meet in the valley. Dev state lives in `.wrangler/state`
- `localhost:5174/akashic` — dev-only asset viewer (`akashic.html`, not in the build): one asset at a time through the game's PS1 pipeline, ←/→ to cycle, `#<id>` deep links, anything that moves on its own plays (A holds it; an asset registers its motion with `assets.ts` `setMotion`), hook `window.__akashic` (ids, select, setView, animate). Check asset edits here before a raid.
- `npm run build` — type check, then production bundle (`npm run preview` serves it): `dist/client/` and the Worker bundle with its generated `wrangler.json`, which `wrangler deploy` is pointed at through `.wrangler/deploy/config.json`
- `npm run typecheck` — `wrangler types` (writes the gitignored `worker-configuration.d.ts`), then strict `tsc -b` over `src`, `tests`, the TS configs, and `worker/`
- `npm run deploy` — build, then `wrangler deploy` to https://bvsw.net (a Workers Custom Domain, declared in `wrangler.jsonc` `routes`; https://bull-valley-shadow-wars.tyler-cbe.workers.dev stays on as a fallback). www.bvsw.net is a second Worker, `worker/www.ts` with `wrangler.www.jsonc`, that 301s every request to the same path on the apex; the deploy workflow ships it after the game. Deploys go through GitHub only, never from a machine: `.github/workflows/deploy.yml` runs it after a green CI run on `main`, with the organization's `CLOUDFLARE_API_TOKEN` secret and the Northern Information account pinned in `wrangler.jsonc`; a `workflow_dispatch` from `main` also deploys
- `npm run lint` / `npm run lint:css` — ESLint (typescript-eslint, type-aware: mark a fire-and-forget promise with `void`; it generates the Workers types first, since the Worker files need them) and Stylelint
- `npm test` / `npm run test:watch` / `npm run test:unit:coverage` — vitest unit tests (`tests/unit/`) and the Worker tests (`tests/worker/`, mock sockets and a stub `cloudflare:workers`); coverage lists every file in `src` and `worker`
- `npm run test:e2e` — Playwright (`tests/e2e/`) against its own Vite dev server on port 5175 in `--mode test` (a fresh valley and accounts database every run, shadow maps off, and the valley runs but is never drawn: CI draws WebGL in software, so specs read the game through `window.__bv`, never its pixels); never against `preview`, since the dev hooks exist only in dev builds. First run: `npx playwright install chromium`
- `npm run pretty` — prettier (sorts imports too); run before every commit. `npm run format:check` checks without writing
- CI (`.github/workflows/ci.yml`) runs on every PR to `main` and every push to `main`: format, lint, types, unit tests with coverage (the pure modules have a per-file floor in `vitest.config.ts`), build, and e2e. The e2e job runs in the Playwright Docker image as three parallel jobs: the `@raid` group, the `@valley` group (the two-page specs, which boot two games each), and every other spec
- `npm run db:migrate` — apply `migrations/*.sql` to the dev server's local D1 (`bull-valley-accounts`, the accounts behind `/auth`); run it once on a fresh checkout and after adding a migration. The deploy workflow applies them to production before each deploy. Local secrets go in a gitignored `.dev.vars` (see `.dev.vars.example`); none are needed, since a dev server signs sessions with a fixed dev secret and offers the Dev provider (`/auth/dev/form`). Production secrets (`JWT_SECRET`, each provider's client id and secret) are set once with `wrangler versions secret put`
- `npm run copy:ai` — list the lines in `COPY.toml` still marked `by = "ai"`
- `npm run images` — regenerate `public/favicon.ico` and `public/apple-touch-icon.png` from `public/favicon.svg`, and the link-preview card `public/og.png` from the logo (needs ImageMagick 7, `brew install imagemagick`)

## The MVP loop

Spawn at a gas station with your wallet (a new account starts with $40) → 5-minute loadout (shop the Citgo) before Matthew Marx's white Chevy leaves → ride the bed, hop out anywhere → find cabbages in the wilderness and carry them as loot → extract at another station, Mt. Coleman's Keep, or call the truck (`T`). If the clock runs out with nobody aboard, Marx crosses Lake Avenue to the field between the road and the corn maze and does donuts there until someone whistles; the called truck drives off the grass to the road and on to them. Tab opens the pack over the valley with the pointer free, on its Consumables tab (Loot, where berries and cabbages go, and Materials sit beside it; `A`/`D` switch): hovering an item shows its card, `E` uses it, and `1`–`9` puts it on the hotbar along the bottom of the screen, whose number keys use it from then on. Shadowmen cross the valley around you and show on the scope (`Q`); one that passes close rushes, and its touch puts you back at the spawn Citgo with everything you had. Beside the spawn Citgo, Gron stands under his own raincloud by the berry bush; talking to him (`E`) changes your name and your character, any time. The Bull Valley Cabbage Stand is set up on the same lot, across the pumps from the sign: scenery only. Under every Citgo sign, Moab Coldë, a burning skeleton in a strapped red trench coat, stands with his back to his burning skeleton horse, facing the lot; `E` beside him and he says his one line in the chat log.

## Multiplayer

One Cloudflare Worker serves the bundle and routes `/ws` to one Durable Object, `ValleyDO`, named `bull-valley`: everyone online is in the same valley and shares one raid. Each socket's player lives in its attachment (WebSocket Hibernation API); the raid lives in the object's storage, and the lobby clock is a storage alarm. The client sends a state frame (`x y z yaw pose riding`) at most `CONFIG.net.sendHz` a second and only when it changed; peers are drawn `CONFIG.net.interpolateMs` behind the present, between their last two frames. Same origin, no CORS. If the socket never answers, the game plays alone and the raid is the player's own.

Chat is one channel for the whole valley, live only: Enter opens the field in the lower left (every key types into it until Enter sends or Esc pauses), a `chat` frame carries the line, and the valley sends it back to everyone, the sender included, under the name it holds and with its own timestamp. Nothing is stored. The text rules (`normalizeChat`, `CHAT_MAX`) are `protocol.ts`'s, and the valley nacks past 5 lines in 10 seconds. Every line in the log carries its local `HH:MM` (the valley's timestamp for a raider's line) and is inked by who said it: raiders blue, NPCs gold, the game's own lines eggshell. Older lines thin out toward the top. The log scrolls with the wheel or PageUp/PageDown (`bindings.ts` `CHAT`) while the field is open, and on hover while paused.

Sign-in is required. The Worker's `/auth` routes (`worker/auth.ts`) sign raiders in with Google, Discord or GitHub (OAuth with PKCE; a Dev provider on dev servers only) and keep the session in httpOnly cookies: a 15-minute access token, a 30-day refresh token. A new raider is held as a pending signup until they pass the 13-or-older and terms gates, then chooses a username (3 to 16 letters, digits or underscores, unique without regard to case). Gron, the hunched NPC beside the berry bush, changes it any time (`PUT /auth/username`) and changes the raider's character too; a `rename` frame then has the valley read the new username from D1 (never from the client), an `appearance` frame carries the new outfit, and everyone gets a `peer-updated` frame. Accounts live in D1 (`bull-valley-accounts`, `migrations/`), and so does what each account looks like: the character and guitar finish chosen at the select or at Gron are saved with `PUT /auth/look` and come back in `/auth/me`, so they follow the raider to any browser; the hotbar is kept the same way (`PUT /auth/hotbar`, the `accounts.hotbar` column). Nothing the game keeps lives in the browser's storage. The Worker reads the access cookie on the `/ws` upgrade and stamps the account and username on the request it forwards; the client never sends a name, and a `hello` with no stamped account is closed `unauthenticated` (4007), which sends the player back to sign in rather than into a solo raid. The client refreshes the session before every socket open. `/auth/me` always answers 200, and so does `/auth/refresh` unless it is rate limited, so a signed-out visitor is not an error.

The shared raid's rules are `src/sharedraid.ts`, a pure reducer the Worker runs and `tests/unit/sharedraid.test.ts` pins: the gas station is a lobby, and the truck leaves when everyone in it is aboard or when the clock runs out, with whoever is aboard (no invisible walls: walking off just means not boarding); one truck, one clock; pickups are shared by index into `world.pickups`, first to ask wins; `T` is one whistle at a time, and the called truck is the caller's until they extract or leave; the valley resets once no one is left in the raid. Every change comes to every client as a whole `RaidWire` snapshot with a reason; `raidsync.ts` `reconcile` says how each client's own `Raid` machine moves from those, and `valleysync.ts` applies it. What each raider hauls is the valley's too, kept per account in the raid so a reload keeps it (`SharedRaid.cargo`, rule 12): a cabbage is taken on foot only while the arms have room, and each `MemberWire` carries its account's `carrying`. The Citgo shelves are shared too: the valley holds every station's stock unit by unit (`RaidWire.shelves`, indexed like `world.fuelPoints`; each item a row of on-the-shelf flags, one per slot), a `buy` frame asks for the unit the buyer is looking at and the `bought` snapshot settles the race, and the shelves fill again with the next lobby; cash is the account's wallet in D1 (`wallets`, a new account starts with $40, and it carries from raid to raid); a buy runs alone in the valley (`blockConcurrencyWhile`), which reads the wallet, refuses a sale it does not cover, and charges it. The client settles the sale locally (`shop.ts` `settle`) once the valley confirms it, and the valley's `pack` frame (the pack and the cash) has the last word. A client whose station count differs is turned away like one whose pickups differ. The berry bush at the spawn Citgo is the valley's too: one berry a day per account, the day turning at midnight Central (`daily.ts`); a `collect` frame asks, the `daily` reply says whether a berry came off, and the welcome carries today's answer. The valley remembers only the accounts that have had today's berry, so two sockets on one account share one berry. Every item a raider carries is their account's pack, in D1 (`packs`, `worker/d1packs.ts`), and the valley alone writes it: the reducer says what goes in or out (`Reduced.pack`: the day's berry, a pickup that is not a cabbage, a unit bought) and a `use` frame takes one out; the welcome carries the pack, and every change sends a `pack` frame to each socket on the account. The client applies its own change at once and takes the valley's pack as the truth when it lands; played alone, the pack starts fresh and nothing is kept. The hello carries every pickup's kind and count (`PickupSpec`), so the valley knows what a take is worth. Account ids never go on the wire. Shared moments are server timestamps read through `clock.ts`: `raidClock` is derived from `startedAt`, and the truck drives against `departedAt` or the call's `at` (`Truck.driveRouteAt`), so every client agrees where it is. A client whose `world.pickups` differ from the raid's, in number or in any pickup's kind or count, is turned away (4005). Positions are not compared, so bump `PROTOCOL_VERSION` whenever placement changes.

Dev only: `?valley=<id>` picks another Durable Object, so parallel e2e specs never meet; `beginRaid` in `tests/e2e/fixtures.ts` gives every page a fresh one unless a spec passes its own. The Worker stamps dev-server sockets, which unlocks the `dev` frames (`hurry`, behind `__bv.hurryTruck`, moves the shared clock; `reset` empties the valley). Production ignores the parameter and the frames.

## Module map

Strict TypeScript throughout. The map (`public/data/bull-valley/`: `geo.json` and the `terrain.png` heightmap) is the game's own, committed and edited by hand; nothing fetches or regenerates it. Shapes that cross modules (world points and heights, geo.json, items, the raid, pack grid entries) live in `src/interfaces.ts`; types one module owns stay in that module.

- `src/interfaces.ts` — shared types only, no runtime code
- `COPY.toml` (repo root) — every player-facing line, each with `text` and `by` (`"ai"` or `"tyler"`); `{name}` placeholders. `src/copy.ts` loads it (Vite `?raw`, so it ships in the client and the Worker) and exports `copy(key, vars)`; `src/copybook.ts` is the pure parsing and filling, shared with `tests/e2e/copy.ts`, which reads the file from disk. `tests/unit/copy.test.ts` fails on a key the code asks for that the file lacks, and on an entry nothing asks for. Modules the e2e specs import (`bindings.ts`, `account.ts`) must not import `copy.ts`: Playwright cannot load `?raw`
- `src/protocol.ts` — pure: the wire protocol, imported by the client and the Worker (frames, close codes, the shown-name rules the stamped username must pass, `parseClientMessage`)
- `src/sharedraid.ts` — pure: the shared raid's rules as a reducer over the valley (lobby, departure, pickups, the whistle, the berry bush, reset)
- `src/raidsync.ts` — pure: the client's side of the shared raid: `reconcile` reads a `RaidWire` snapshot against the one before and says how the raider's own `Raid` moves (the truck leaving with them or without, a whistle answered, the valley's word on their haul); `seatOf` the bed seat, `lobbyCount` the lobby headcount, `departureKind` the joyride or, on an empty bed, the donuts (seeded by the raid's epoch, so every client draws the same)
- `src/daily.ts` — pure: the daily clock behind the berry bush (the Central calendar day of an instant, the next midnight Central, DST included); the Worker runs it against its own clock
- `src/clock.ts` — pure: the server-clock offset from ping round trips
- `src/presence.ts` — pure: the peer table, two-frame interpolation, Scaduscope contacts
- `src/net.ts` — the WebSocket client: a session refresh before each open, hello, reconnect with backoff, pings; `ready` resolves online or offline, and `onRefused` hears a 4xxx close
- `src/account.ts` — pure: the `/auth` protocol shared by the client and the Worker (providers, the username rule, wire shapes, redirects, the `?auth=` return flags)
- `src/cookies.ts` — pure: the session cookie names, parse and serialize
- `src/auth.ts` — the client's calls to `/auth` (who is signed in, refresh, confirm signup, username, sign out)
- `src/signin.ts` — the account step between the logo and the select: the sign-in card, then Choose Your Username with the age and terms gates and the terms overlay (`public/terms.html`)
- `src/grondialog.ts` — talking to Gron (E beside him): change your username, and change your character and guitar finish on a small turntable preview. The pointer comes free while it is open and the game's keys stand aside; `actions.ts` applies the changes and tells the valley
- `src/accountpanel.ts` — the account panel, opened from the Account link on the select or the pause overlay: linked providers with Unlink (never the last), Link Another Account in a popup that lands on `public/auth-done.html` (which posts the result back and closes; a blocked popup falls back to a full-page round trip), and Sign Out. While it is open, the select's keys are its alone
- `worker/auth.ts` — the `/auth` routes and the identity stamp on the upgrade; `worker/oauth.ts` the provider flow, `worker/tokens.ts` the JWTs (`jose`), `worker/accounts.ts` the store interface and an in-memory store for tests, `worker/d1accounts.ts` the D1 store (the look too), `worker/packs.ts` the pack store interface and an in-memory store, `worker/d1packs.ts` the D1 pack store, `worker/env.ts` the secrets and origins, `worker/ratelimit.ts` the rate limits (two bindings in `wrangler.jsonc`: strict at 10 a minute for the routes that start a sign-in or change an account, loose at 60 for the username check, the session refresh and the look; keyed by account, then pending signup, then client address; the dev provider, `/auth/me`, sign-out and the callback are never limited; a limiter error lets the request through)
- `src/peers.ts` — the other players in Three: one `figure.ts` body per peer and a pixelated name sprite
- `worker/index.ts` — the Worker router (`/ws` to the valley, everything else to the assets binding, the dev stamp); `worker/ValleyDO.ts` — the Durable Object: sockets, storage, the alarm, and the reducer. Checked by `worker/tsconfig.json` with Workers types, so the Worker tests live in `tests/worker/`, not `tests/unit/`; `worker/www.ts` — the www redirect, a Worker of its own (`wrangler.www.jsonc`)

- `src/main.ts` — boot: loads the survey, builds the scene and the systems into one `Game`, and hands it to the modules below. Game rules go in the pure modules, never here or in them
- `src/game.ts` — the `Game` boot builds (the systems) and the `GameState` they share (the raid, the pack, the wallet, the shared raid, the pending asks, the item effects)
- `src/titles.ts` — the colophon, the logo, the account step and the character select, in order; resolves with the username and the pick. A raider whose account has chosen a character (`characters.ts` `hasChosen`) skips the select; Gron changes it from then on, and the pause overlay carries Raiding As, Account and Sign Out
- `src/actions.ts` — what the player does (board, hop out, take, buy, the berry, use an item, whistle, talk, extract, the pack and the hotbar): alone it moves the raid at once, in the shared valley it asks the valley
- `src/valleysync.ts` — what the valley says, applied: peers and chat, then each raid snapshot through `raidsync.ts` `reconcile`, the nacks, the pack
- `src/input.ts` — pointer lock (start, pause) and the keys, looked up in `bindings.ts`: the pack's first while it is open, then the chat field's, then the valley's
- `src/targets.ts` — what E is aimed at (the store, the shelf unit in view, the NPCs in reach), what the glow rings, and where an item's label floats
- `src/loop.ts` — the frame: the clocks, the ride or the walk, the shadowmen and mist, the maze portal, the state frame, the HUD and the hotbar, the interaction, the draw
- `src/devhook.ts` — `window.__bv`, installed last in dev builds
- `src/raid.ts` — pure raid state machine (LOADOUT → RIDING → ON_FOOT → EXTRACTED), the loadout clock, `canPick` and `timedOut`
- `src/bindings.ts` — pure: every key in one table (`WORLD` in the valley, `PACK` with the inventory open), each with its codes, the key label, and the `COPY.toml` key of the action label (`labelKey`). `input.ts` and `player.ts` look actions up here (`actionOf`, `moveAxis`, `isHeld`); `hud.ts` draws the intro controls table and the pack's keys (the item card, the grid's foot) from it. The number keys are one binding: the hotbar in `WORLD`, assigning in `PACK` (`hotbarSlot`). Rebind a key here and nowhere else; reword it in `COPY.toml` `[keys]`
- `src/interactions.ts` — pure: what E would do right now (board, hop out, extract, take a pickup, buy a shelf unit, pick the day's berry, talk to Gron, speak to Marx, Carlsten or Moab) and what says so: an item (a pickup, the shelf unit a buy takes, the berry bush) gets just its name floating over it (`itemLabel`, drawn by `hud.ts` `itemLabel` at the item's projected top), the people you talk to get no prompt (their glow says it), everything else the bottom prompt (`interactionPrompt`); `loop.ts` resolves it each frame. `dailyStatus` reads the berry bush against the valley's clock
- `src/npcs.ts` — pure: Marx's, Carlsten's and Moab's lines (`COPY.toml` `[marx]`, `[carlsten]`, `[moab]`), cycled per player. `interactions.ts` answers with the nearest within reach (`CONFIG.npcs.reach` for Marx at `Truck.driverAt` and Carlsten at `world.clerks`, `CONFIG.moab.reach` for Moab at `world.moabs`), unless a shelf unit is in view
- `src/shop.ts` — pure: one purchase off a Citgo shelf (`buy`, returning new raid, stock, inventory, and cash) and the buyer's side alone (`settle`), which the shared valley applies once a sale is confirmed
- `src/store.ts` — pure: the walk-in Citgo every station shares — `STORE_LAYOUT` (shell, fixtures, fluorescent lights, shelf facings, and the wall signs in station-local space, read by `assets.ts` and `world.ts`), fresh shelf stock, which unit the player is looking at (`unitInView`: each unit by its own slot), `formatCash`. Every station sells 3 of every item; a new account's wallet starts at $40 and carries from raid to raid
- `src/adart.ts` — canvas art for the advertisements on the Citgo walls, keyed by `AdId`; prices on them come from `items.ts`
- `src/walls.ts` — pure: the only things that stop you (the store walls and fixtures, the berry bush, Gron, the cabbage stand, Moab and his horse, the utility poles and streetlights), as capsules on a spatial hash; `Player` resolves against `world.walls` after every move
- `src/roadgraph.ts` — pure road-network graph, Dijkstra, arc-length walker; `callRoute` is the whistle's route, from wherever the truck is (off the road included) onto the roads and to the caller
- `src/donuts.ts` — pure: Marx's donuts, a seeded path from the parked truck to the field (`CONFIG.truck.donuts`, station-local; `world.donutField`, kept clear of trees) and then sets of loops, figure-eights and dashes, each picking up where the last left off and drawn only where it fits inside the field
- `src/roadside.ts` — pure: what stands beside the roads, on its own seed. Utility poles in lines along the named roads (crossarms square to the road; consecutive poles of a line carry wire), sodium streetlights at the junctions a tertiary-or-bigger road passes through, and the carriageway widths `world.ts` draws the roads at. `world.ts` tiles the poles so frustum culling skips most of the valley; each lamp gets a halo, a pool of light draped on the ground, and a few real lights ride to the lamps nearest the player
- `src/ground.ts` — pure: what to stand on at any point. The terrain is a heightfield and the roads, station lots and mud trails (`addTrail`, draped on the terrain) float a little over it; `world.ts` registers those surfaces on a `Ground`, and `world.ground.at(x, z)` returns the terrain or the surface deck, whichever is higher. The player, the truck, and every placed thing stand on `ground.at`; only the terrain mesh and the surfaces themselves sample the raw `heightAt`
- `src/truck.ts` — the white Chevy: seats the driver in the `assets.ts` body (he reads a paperback by the tailgate through the lobby, then walks round to his door before the truck leaves); the headlights and taillights are shadow-casting spots, and the roads are lit so the beams show on them; drive/board/ride/call; `driveRouteAt` drives against a shared clock, `driveDonuts` the same with the nose swung into the turn, and the bed has numbered seats
- `src/figure.ts` — the shared character body: rigid low-poly parts on joint pivots, built per outfit; `applyPose` drives it. `buildGron` is Gron as he stands: the `gron` outfit (not on the roster) in the `hunch` pose under his raincloud (`assets.ts` `buildRaincloud`), placed by `world.ts` at `CONFIG.gron`. `buildMoab` is Moab Coldë: the `moab` outfit (not on the roster) standing with his back to `assets.ts` `buildSkeletonHorse` (`MOAB_BESIDE`) in the `wield` pose, a burning `buildScroll` held out in his right fist and a `buildScythe` taller than him in his left, turning his head slowly, with `buildFlames` (tongues, halos, sparks and smoke) on his posed joints and his head and `buildFireRoots` writhing over the ground from his feet; the horse idles on its own pivots (breath, nod and look, tail swish, a forehoof stamp). `world.ts` places one under every station's sign at `CONFIG.moab`
- `src/outfits.ts` — pure: every character outfit in one table (colors by slot, add-on parts, limb proportions); edit characters here
- `src/poses.ts` — pure: the body's joints, the poses (stand, sit, lean, read, crouch, hunch, wield, walk cycle) and `samplePose`
- `src/playerbody.ts` — the player's own legs in first person: the outfit picked at the character select, torso hidden, posed from the move speed
- `src/characters.ts` — pure: the selectable roster (in select-screen order) and the account's pick with its defaults (`pickOf`)
- `src/characterselect.ts` — the character select: one figure on a PS1 turntable with its own small renderer (the game's does not exist yet), mounted at boot beneath the account step and the title cards. It shows the account's username ("Raiding as") with Account and Sign Out
- `src/finishes.ts` — pure: the guitar finishes in one table and the random draw; the select shows the row for any character with a guitar on their back
- `src/cabbages.ts` — pure seeded cabbage placement
- `src/maze.ts` — pure: the corn maze across Lake Avenue from the spawn Citgo, The Shining's hedge maze traced as a character grid (`SHINING_MAZE`), its walls as straight runs and the pieces they are drawn in, the worn trail down the middle of every path (`trailField`, the ridge of the distance to the corn), the lamp spots round it, and the portal check. `world.ts` plants it at `CONFIG.maze` (station-local) on `ground.at`: one `Walls` capsule per run, sodium lamps round the outside (with the streetlights), CORN MAZE! and ENTER! signs, a mud trail out of the gate to the road, and the trees kept out. At its heart a portal (`assets.ts` `buildPortal`, `world.portal`) puts anyone on foot who walks into it back outside the gate (`loop.ts`). Shadowmen still walk through the corn. `src/mazeart.ts` paints the stalks, the signs and the portal's swirl
- `src/standart.ts` — canvas art for the painted board on the cabbage stand (`assets.ts` `buildCabbageStand`, placed by `world.ts` at `CONFIG.stand` on the spawn Citgo's lot)
- `src/mudart.ts` — canvas art for worn mud: the tiling strip on every road's shoulders and the trail out of the maze (`world.ts` registers both on the `Ground` as trails), and the maze's own trail painted from `trailField`. Station lots are 40 m wide (`FUEL_LAYOUT.lot`)
- `src/items.ts` — pure: every item in one table (tuning, starting count, price in cents; the label, blurb and log lines come from `COPY.toml` `[items.<id>]`); edit items here. Meshes stay in `assets.ts`, keyed by id
- `src/canvas.ts` — shared 2D canvas helpers (`context2d`, `canvas`, `text`, fonts: `MONO` for UI text, `SERIF`/`SANS` for trade dress) for the painted art
- `src/packart.ts` — canvas trade-dress art for the cigarette packs
- `src/drinks.ts` — pure: drink container sizes and the per-family fit height; the drinks themselves (circa 2008, for sale at every Citgo, no effect yet) are entries in `items.ts`
- `src/canart.ts` — canvas trade-dress art for the drink labels, as they looked circa 2008
- `src/medart.ts` — canvas art for the medicine labels (a pill bottle, a carton, a dropper bottle); the medicine itself (aspirin, ibuprofen, Benadryl, eye drops, on the rack by the register, no effect yet) is entries in `items.ts`, and `assets.ts` builds one shape per `MedicineForm`
- `src/decalart.ts` — canvas art for the decals on character parts (prints over the torso, thighs and arms; the buckle face); outfits name them by `DecalId`
- `src/chat.ts` — pure: the chat log (the lines it keeps, when it fades) and the game's own lines to the player; `hud.ts` draws it. Everything the game tells the player goes into the log as a system line (`hud.tell`), worded in `COPY.toml` `[log]`
- `src/inventory.ts` — pure: the pack's transforms (`addItem`, `useItem`, `toInventory`), using an item with its timed effect (`consume`: the smoke, the ember, perception, as `hotbar.ts` `Effects`), and the starting pack; the pack itself is the account's (sharedraid rule 11)
- `src/packgrid.ts` — pure: the pack's tabs (`PACK_TABS`: Consumables, Loot, Materials) and which items fill each (consumables by category; loot is the berries and the cabbages; nothing is a material yet), in order, and any kind as the hotbar shows it, carried or not
- `src/hotbar.ts` — pure: the hotbar's nine slots (`assign`, the wire check `isHotbar`) and the cooldown sweep over a slot (`cooldownOf`: every cigarette waits on the one burning, then its ember; the joint shows perception). There are no effect timers elsewhere
- `src/itemthumbs.ts` — the items as the pack and the hotbar draw them: one plain antialiased renderer of its own, off screen, that draws each item once into a still icon and spins the hovered one on the item card
- `src/cycle.ts` — pure: `stepIndex`, the wrapping step the character select and Gron's turntable share
- `hud.ts` draws the pack (its tabs over a grid of 50px cells on translucent black over the valley, which keeps drawing; the player freezes, the raid clock does not), the item card inside it, and the hotbar. The pack frees the pointer, as Gron's dialog does; Tab, Esc or a click past it closes it and locks the pointer again
- `src/landmarks.ts` — consented landmark coordinates + projection, and the cabbage patch the guaranteed cabbages grow round (`CABBAGE_PATCH`)
- `src/splashmachine.ts` — pure: the title-card state machine (triangle-wave fade, gesture and skip latches)
- `src/splash.ts` — the title-card DOM overlays (the Northern Information colophon, then the logo), driven by `splashmachine.ts`; `COLOPHON` and `LOGO` add the cards' words to `CONFIG`'s timings, so `config.ts` never loads the copy book
- `src/fog.ts` — the logo card's black fog: one plain-WebGL fragment shader (fbm noise in rolling waves) at the game's downscale
- `src/assets.ts` — every 3D asset in asset-local space (instanced parts, one-off builders, the truck body, the sky, the road/water/fence/boundary materials) and the Akashic registry; new assets go here
- `src/world.ts` — places terrain features, Citgo stations, pickups, beacons from geo.json using `assets.ts`; builds no materials of its own. Each store stands level over its slope on a foundation (`store.ts` `storeBase`), registers its floor on the `Ground` and its walls on `Walls`; one stocked shelf display, with David Carlsten (the `carlsten` outfit, not on the select roster) behind the counter, follows the player to the nearest store
- `src/akashic.ts` — the Akashic asset viewer
- `src/terrain.ts` `src/player.ts` `src/coords.ts` `src/ps1.ts` `src/rng.ts` `src/config.ts` `src/hud.ts` `src/scope.ts` — ported engine
- `src/audio.ts` — the title-card cues (`playOneShot`); the game has no other sound
- `src/glow.ts` — the Citgo-red ring around whatever E would act on (a pickup, the shelf unit a buy takes, the bush while today's berry is on it, Gron, Marx, Carlsten or Moab when E would talk to him; never players, the truck, or an extraction): the target alone into a mask with its own materials, then a dilated outline over the frame, x-ray through what stands in front. `GLOW_LAYER` (1) is reserved for it; the scene's lights sit on it too, so the mask pass sees the same light set
- `src/shadowmen.ts` — pure: the shadowmen as crossings in a bubble that follows the player (spawned on a ring past scope range, dropped past `despawnRadius`), the rush when one passes close to a player on foot, the touch that is a strike, and the Citgo havens; feeds the scope. Tune them in `CONFIG.shadowmen`
- `src/shadowcards.ts` — the silhouette cards that show `shadowmen.ts` (textures, aura, flicker), one card per field slot
- `src/mist.ts` — pure: the ground mist as banks drifting on the wind through a square bubble that follows the player (wrapping to the far side), each swelling and thinning on its own period; atmosphere only, it hides nothing. Tune it in `CONFIG.mist`
- `src/mistcards.ts` — the soft posterized cards that show `mist.ts`, standing on `ground.at` with their skirts sunk into the terrain, one card per bank; they take the scene fog, and hold still under prefers-reduced-motion

Pure logic stays Three-free (like `coords.ts`); Three/DOM glue lives in `truck.ts`/`world.ts`/`hud.ts`. Many pure modules still load `COPY.toml` through `copy.ts` (`items.ts` carries the item labels), so an e2e spec can import only the ones that do not. Dev introspection hook: `window.__bv` (scene, camera, renderer, player, world, truck, graph, shadowmen, mist, raid, net, shared, daily, aboard, glow, cash, inventory, hotbar, chat, teleport, hurryTruck).

## Typography

IBM Plex Mono everywhere (`public/fonts/IBMPlexMono-*.woff2`: regular, italic, semibold and bold, the Fontsource latin subset, OFL), self-hosted; every page preloads regular, semibold and bold, and italic loads on demand; the tokens are `--bv-font` and `--bv-text-size` (1rem) in `index.html`. `boot()` awaits `fontsReady()` before it builds any DOM, and the face is `font-display: block`, so no text ever paints in a fallback and reflows; canvas UI text (the scope, peer name tags) uses `MONO` from `canvas.ts` and draws after the gate. The trade dress on packs, cans, medicine and the Citgo signs keeps its own period faces. A label that changes in place must not resize its box: the Begin button stacks every label in one grid cell (`bv-btn--stack`, `Hud.setBegin`), and the account status holds one line even when empty.

## Testing in a browser

- Use `channel: 'chromium'` (full Chromium in headless mode) for Playwright. The default headless shell draws WebGL in software on macOS at about 2 fps, which is too slow to drive a raid. On CI there is no GPU at all, so specs take about 3 times longer; `playwright.config.ts` gives them longer timeouts when `CI` is set.
- Boot runs colophon → logo → account step → character select → intro. Each title layer is black and stacked over the next, and a layer's keys arm only once it is showing: Space starts the colophon, Space skips it and then the logo, ←/→ and Enter choose. The select shows only until the account has chosen a character; `passTitles` handles both, and `passReturning` expects the select to stay away. While the pointer is free a Citgo-red edge glows round the view. The account step shows only without a session (the sign-in card) or without a username (Choose Your Username); a page landing from a sign-in round trip (`?auth=`) skips the colophon and the logo. `?skipSplash` skips the titles in dev with the saved pick; with no session it first signs in a dev raider named "Raider" and comes back.
- Specs sign in before they load the game: `signIn` in `tests/e2e/fixtures.ts` goes through the dev provider with a fresh `freshRaider()` (a tagged username, since parallel specs share one accounts database) and lands on `auth-done.html`; `beginRaid` signs in, then loads `/?valley=…` and `passTitles` drives the select. Two pages that must be two raiders need two browser contexts, since the session is a cookie. Under `--mode test` the dev server keeps its state in `.wrangler/state-test`, which the Playwright server command empties and migrates first.
- Wait for `window.__bv` before you click Begin. `boot()` sets the hook last, after the input listeners. The button reads "Click to Play" as soon as input wiring starts, before the hook is set, so its text is not a ready signal.
- To prove that a refactor changes no asset, render every Akashic asset on `main` and on the branch from the same fixed view (`__akashic.animate(false)`, then `select(id)` and `setView(35, 20)`). Compare the `.ak-stats` text and a hash of the canvas screenshot. Serve `main` from a `git archive` copy with a symlink to this repo's `node_modules`.

## Standing rules

1. The map never includes driveways, private service roads, or buildings. Edit `public/data/bull-valley/` by hand, and bump `PROTOCOL_VERSION` whenever a change moves where things are placed.
2. No GPS EXIF in any media added to the repo.
3. Landmarks are consented or public places only. Keep the consent comments in `src/landmarks.ts`.
4. The `three`/`vite` pins are deliberate: `ps1.ts` patches Three shader chunks via `onBeforeCompile`, and Three minors rename chunks. Upgrading is its own task.
5. `public/data` is intentionally minified; it is in `.prettierignore`.
6. It's a raid, not a run — in code, copy, commits, and docs.
7. Nothing stands on the raw terrain. Place and move things with `world.ground.at`, and register any new walkable surface (a floor, a deck, a lot) on the `Ground` in `world.ts` before placing on it.
8. One truck, one clock, shared pickups, shared shelves, one berry a day per account, and every item in the account's pack and every cent in its wallet, and each raider's haul, kept by the valley. No game state is kept in the browser. A rule of the shared raid belongs in `src/sharedraid.ts` with a test, never in the Worker or in the client glue (`main.ts`, `actions.ts`, `valleysync.ts`, `loop.ts`); the client's reading of a snapshot belongs in `src/raidsync.ts`, also with a test.
9. Player-facing text lives in `COPY.toml`, never inline in code: add the entry, then call `copy('section.key')`. Anything an AI writes or rewrites there is `by = "ai"`. Never set `by = "tyler"`, and never change the text of a `"tyler"` entry unless Tyler asks. Tests and specs assert copy through `copy()`, never as literals, so editing a line never breaks a test. Out of the file: `public/terms.html`, `public/auth-done.html`, the `index.html` meta tags, provider names, the Akashic page, and painted trade dress.
