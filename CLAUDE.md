# Bull Valley Shadow Wars

An adventure RPG set in a hauntological Bull Valley, Illinois. 3D first-person in the browser, WASD + mouse, PS1 aesthetic. The engine was ported from forgotten-industries' ground-survey spike (provenance sha in the first commit); the spike's branding is gone — this is Bull Valley Shadow Wars. The valley is one persistent world that everyone online shares; its players are **raiders**. The raid (a session that ends at an extract) is set aside for now and will come back; until then nothing in the game starts or ends a raid.

## Commands

- `npm run dev` — Vite dev server on port 5174. The Cloudflare Worker and its Durable Object run beside it in workerd (`@cloudflare/vite-plugin`), so this is the whole stack: open two windows and they meet in the valley. Dev state lives in `.wrangler/state`
- `localhost:5174/akashic` — dev-only asset viewer (`akashic.html`, not in the build): one asset at a time through the game's PS1 pipeline, ←/→ to cycle, `#<id>` deep links, anything that moves on its own plays (A holds it; an asset registers its motion with `assets.ts` `setMotion`), hook `window.__akashic` (ids, select, setView, animate). Check asset edits here before a raid.
- `localhost:5174/akashic#map` (or `M` in Akashic) — the map editor: the survey from above over a hillshade of `terrain.png`, every layer toggled on its own. Drag to pan, scroll to zoom, click to select (the panel on the right names it, sets a road's class or water's kind, measures it); drag a point to move it, drag a selected feature (or any fuel point) to move it whole, double-click an edge to add a point, Del removes the point (Shift-Del the feature), arrows nudge, `N` draws a new feature on the chosen layer (Enter ends, Esc cancels), ⌘Z/⌘⇧Z, ⌘S saves. Saving POSTs the survey to the dev server (`vite.config.ts` `akashicMapSave`), which checks it (`mapedit.ts` `isGeo`, the frame unchanged) and writes `geo.json` back minified; under `--mode test` it refuses. Bump `PROTOCOL_VERSION` when a save moves where things are placed (rule 1). Hook `window.__akashic.map`
- `npm run build` — type check, then production bundle (`npm run preview` serves it): `dist/client/` and the Worker bundle with its generated `wrangler.json`, which `wrangler deploy` is pointed at through `.wrangler/deploy/config.json`
- `npm run typecheck` — `wrangler types` (writes the gitignored `worker-configuration.d.ts`), then strict `tsc -b` over `src`, `tests`, the TS configs, and `worker/`
- `npm run deploy` — build, then `wrangler deploy` to https://bvsw.net (a Workers Custom Domain, declared in `wrangler.jsonc` `routes`; https://bull-valley-shadow-wars.tyler-cbe.workers.dev stays on as a fallback). www.bvsw.net, bvsw.gay and www.bvsw.gay are a second Worker, `worker/www.ts` with `wrangler.www.jsonc`, that 301s every request to the same path on the apex (each host a Custom Domain there, so its zone must be on the Northern Information account); the deploy workflow ships it after the game. Deploys go through GitHub only, never from a machine: `.github/workflows/deploy.yml` runs it after a green CI run on `main`, with the organization's `CLOUDFLARE_API_TOKEN` secret and the Northern Information account pinned in `wrangler.jsonc`; a `workflow_dispatch` from `main` also deploys
- `npm run lint` / `npm run lint:css` — ESLint (typescript-eslint, type-aware: mark a fire-and-forget promise with `void`; it generates the Workers types first, since the Worker files need them) and Stylelint
- `npm test` / `npm run test:watch` / `npm run test:unit:coverage` — vitest unit tests (`tests/unit/`) and the Worker tests (`tests/worker/`, mock sockets, a stub `cloudflare:workers`, and `tests/worker/stubs/d1.ts`, a D1 on Node's own SQLite with every migration applied, so the D1 stores run their real SQL); coverage lists every file in `src` and `worker`, though a file no test imports reads 0 of 0 (so 100%): give any module under a floor a test
- `npm run test:e2e` — Playwright (`tests/e2e/`) against its own Vite dev server on port 5175 in `--mode test` (a fresh valley and accounts database every run, shadow maps off, and the valley runs but is never drawn: CI draws WebGL in software, so specs read the game through `window.__bv`, never its pixels); never against `preview`, since the dev hooks exist only in dev builds. First run: `npx playwright install chromium`
- `npm run pretty` — prettier (sorts imports too); run before every commit. `npm run format:check` checks without writing
- CI (`.github/workflows/ci.yml`) runs on every PR to `main` and every push to `main`: format, lint (ESLint and Stylelint), the migrations check (`scripts/check-migrations.sh`), types, unit tests with coverage (the pure modules and every Worker file have a per-file floor in `vitest.config.ts`), build (`build:only`, the types having run already), and e2e. The e2e job runs in the Playwright Docker image as three parallel shards (`--shard`, the jobs named `E2E tests (1/3)` and on), then `E2E shard balance` says how evenly they split (below, E2E shards)
- `npm run db:migrate` — apply `migrations/*.sql` to the dev server's local D1 (`bull-valley-accounts`, the accounts behind `/auth`); run it once on a fresh checkout and after adding a migration. The deploy workflow applies them to production before each deploy. Local secrets go in a gitignored `.dev.vars` (see `.dev.vars.example`); none are needed, since a dev server signs sessions with a fixed dev secret and offers the Dev provider (`/auth/dev/form`). Production secrets (`JWT_SECRET`, each provider's client id and secret) are set once with `wrangler versions secret put`; `MAGIC_WORD` is the repository's GitHub secret of the same name, which the deploy workflow uploads to the Worker on every deploy (rotate it there, then dispatch a deploy); without it production takes no new raider, and a dev server takes "berries"
- `npm run copy:ai` — list the lines in `COPY.toml` still marked `by = "ai"`
- `npm run images` — regenerate `public/favicon.ico` and `public/apple-touch-icon.png` from `public/favicon.svg`, and the link-preview card `public/og.png` from the logo (needs ImageMagick 7, `brew install imagemagick`)

## The MVP loop

Spawn at the gas station with your wallet (a new account starts with $40), or wherever your account last stood on foot. Every 30 to 90 seconds a few slurms (black slugs, after the worms of _Out of This World_, each with one white tooth it bares and takes back in) drop off a Citgo's dripline, the store's front eave or an edge of the pump canopy, sometimes several at once; David Carlsten comes out from behind the counter with his bat, smashes each one, curses in the log of whoever is near (`COPY.toml` `[slurms]`, in turn), and walks back in. Scenery only: they never touch a raider, and everyone at that Citgo sees the same drop (`slurms.ts`, on the shared clock). The valley's music, the Bull Valley Scaduscope theme, loops quietly under everything from the main menu on, and from Begin on the valley's sounds (so far the strikes, the flashlight, the burns and bursts, the spiders and the Caretaker, heard from where they happen) play over it; a Music and a Sounds slider in the main menu's Audio and on the pause overlay set how loud. Shop the Citgo. Matthew Marx's white Chevy is parked by the spawn Citgo, Marx reading at the tailgate; he reads for five minutes, then crosses Lake Avenue to the field between the road and the corn maze and does donuts for five, then drives home and reads again, over and over, and anyone arriving in the valley while he is at his donuts brings him straight home. Climb into the bed (`E`) and a 60-second countdown starts for everyone, and the first one in gets the map (`citgomap.ts`, opened for a charter): a click anywhere picks where he goes (snapped to the nearest road), Esc leaves it to him, and `E` hops out. When the countdown runs out he takes whoever is in the bed there and lets them off, then drives home empty, or with no pick on the joyride out through the valley and home again, letting them off at the Citgo. With no one else in the valley no countdown shows: he leaves as soon as the pick is made. Hop out (`E`) anywhere. `T` whistles for him from anywhere while his bed is empty: he drives to you, you climb in, and he drives you home. Find cabbages in the wilderness and in the shade under the dishes behind the spawn Citgo (`cabbages.ts` `placeDishCabbages`, `CONFIG.cabbage.underDishes`), and they go into your pack, under Loot. Pickups, the Citgo shelves and whatever lies dropped all come back with the day, at midnight Central. Tab opens the pack over the valley with the pointer free, the raider standing on a turntable beside it in their character and whatever they wear (`avatarview.ts`; the Flaming Halo too), on its Consumables tab (Loot, where berries and cabbages go, Key Items, and Materials sit beside it; `A`/`D` switch): hovering an item shows its card, `E` uses it, `1`–`9` puts it on the hotbar along the bottom of the screen, whose number keys use it from then on, and `X` drops one (the open pack or bottle, or one of anything else) a little ahead of you, Shift-`X` the whole stack. `1`–`9` with no item under the cursor empties that slot, and a kind the pack runs out of (the last one used, dropped or stowed) leaves the bar on its own. The mouse works the open pack too (`packhud.ts` `wireMouse`, `bindings.ts` `PACK_MOUSE`): a click pins an item's card so the keys act on it, a double-click uses it, a drag puts it on a hotbar slot (every slot shows while the pack is open; a slot dragged off the bar or right-clicked empties), a right-click opens a menu of everything it can do, and at the locker a Shift-click moves the whole stack. Anyone can take a drop up with `E`, as with any pickup; drops lie there until the day turns. The raider's state of mind is four wards, shown in the upper left as a red tetrahedron turning on its point (`vitalshud.ts`, `wards.ts` `tetraView`), each corner glowing with its level and carrying its mark (`icons.ts`: a weed leaf for high, a pill for stimulated, a beer bottle for drunk, a blotter tab for tripping): high the joint (and a little off the psychedelics), stimulated cigarettes, the energy drinks and anything swallowed as a pill (Adderall, aspirin, ibuprofen, Benadryl), drunk beer and liquor (Four Loko does both, and water sobers a little), tripping LSD and mushrooms (eye drops bring high and tripping down); each fades on its own (`CONFIG.geometrie`). Each is a layer of armor against its own shadows (`wards.ts`, `CONFIG.wards`): high against the shadowmen, stimulated against the spiders and spiderlings, drunk against the Caretaker, tripping against the tunnel shades and the Warden, the matching corner cutting a touch by up to 60% and the strongest other by up to 10% more; a chip under the bar for every ward going shows its strength. High also reaches the flashlight's beam further and wider, and stimulated quickens the sprint (`buffs.ts`, `CONFIG.buffs`). Every buff going (each of the four wards, and the joint's perception) shows as a cell in a row over the hotbar (`buffbar.ts` `activeBuffs`, `buffhud.ts`), its left edge on the bar's first slot (or, with nothing on the bar, where the bar would be), its mark under a dark wedge that grows as it winds down and the time left under it. Anything smoked, drunk or swallowed can be passed instead (`G`: over an item in the open pack, or in the valley the last thing used) to a raider on foot within `CONFIG.buffs.passReach` in front of you: they take it in full, its dose and its heal, and the giver catches a share of the dose (`shareScale`) and XP for sharing. Anything smoked or drunk also blurs the view for a second and then trails it for as long as it lasts (a cigarette while it smokes, the joint two minutes, each drink its own). Shadowmen cross the valley around every raider, the same ones for everyone; one that passes close rushes, and in reach it draws back, winds up (`CONFIG.shadowmen.windupSeconds`) and lunges, every shadow the same and for everyone to see; a lunge lands only if you are still in reach, so a step back makes it miss. Every raider has geometrie, their hit points: 1,000 at level 1 and 40 more a level (`health.ts` `maxGeometrie`, `CONFIG.health`; 4,920 at level 99), shown Dark Souls style as a chunky red bar beside the tetrahedron in the upper left, as long as the raider's whole (it grows with the level), a pale trail of what a touch took draining after the fill, the points and the level on it. Each shadow's touch takes its own hit (`CONFIG.damage`: a spiderling 140, a shadowman 320, a tunnel shade 420, a spider 480, the Caretaker 750, the Warden 1,100, each give or take 10% on the valley's roll), cut by the wards (`wards.ts` `damageOf`); the number pops under the bar with what the wards took off it in the ward's colour (`hud.ts` `popDamage`, touches close together adding up), the view washes red and shakes, the first ward to take the edge off says so in the log, and the touch leaves you where you stand with a few seconds' grace (`CONFIG.health`). The touch that takes the last of it shatters your geometrie (GEOMETRIE SHATTERED over the static) and puts you back at the spawn Citgo, whole, with an empty pack: everything you carried stays on your body where you fell (a corpse run). Standing on any Citgo forecourt makes you whole, and everything smoked, drunk or swallowed gives geometrie back as it moves the wards (`items.ts` `healsPct`, a share of whole: 15% for a cigarette, a drink, water or a pill, 30% for the joint, LSD, mushrooms, Four Loko and the liquor; never past whole). ## Multiplayer

One Cloudflare Worker serves the bundle and routes `/ws` to one Durable Object, `ValleyDO`, named `bull-valley`: everyone online is in the same valley and shares one persistent world. Every change to the valley runs under one lock in `ValleyDO` (`locked`): the reducer runs and its result is applied with nothing between, D1 writes included, so the shadowmen's step never lands between a handler's reduce and its apply (`blockConcurrencyWhile` holds inbound events, not the step's timer, so only the constructor's storage read uses it); what is one account's alone (the season's and the daily task's tallies, the Book of Shadows) runs under that account's own lock (`forAccount`). State frames and chat touch no valley and never wait on either. Each socket's player lives in its attachment (WebSocket Hibernation API); the world lives in the object's storage, and a storage alarm wakes it for Marx's next change and the day's turn while anyone is online. The client sends a state frame (`x y z yaw pitch pose riding light`, light being the flashlight up and on) at most `CONFIG.net.sendHz` a second and only when it changed; peers are drawn `CONFIG.net.interpolateMs` behind the present, between their last two frames. Same origin, no CORS. If the socket never answers, the game plays alone and the valley is the player's own, Marx's day included (the client runs `marx.ts` against the wall clock).

Chat is one channel for the whole valley, live only: Enter opens the field in the lower left (every key types into it until Enter sends or Esc pauses), a `chat` frame carries the line, and the valley sends it back to everyone, the sender included, under the name it holds and with its own timestamp. Nothing is stored. A line starting with `/` is a command answered in the typer's own log and never sent (`chat.ts` `chatCommand`): `/online` names everyone in the valley, each with their level, `/emotes` lists the emotes, and an emote's own name takes it: `/wave`, `/sit`, `/smoke`, `/dance`, `/point`, `/shrug`, `/kneel` (`emotes.ts`). An emote is a pose (`poses.ts`) the raider's body takes, carried to everyone by the state frame's `pose` field (`protocol.ts` `PEER_POSES`, named as typed), so nothing else goes on the wire; a raider within `CONFIG.emotes.seenRadius` of one beginning gets a quiet line in the log (`seenEmote`, `chat.ts` `emoteLine`), and the emoter's own log says what they did. Each holds for its seconds (`/sit`, `/kneel` and `/dance` until the raider moves), and moving, crouching, boarding or a strike ends it; sitting and kneeling lower the eye. Never from the bed. Friends and whispers (rule 21, `friends.ts`) are commands too, sent to the valley rather than said: `/w name message` (or `/whisper`) goes to that raider's sockets alone and back to the sender's, inked pink, under the chat rules and the chat rate, never stored; `/friend name` asks a raider to be friends (or accepts their asking: the two are friends once both have asked), `/unfriend name` ends it or takes a request back, and `/friends` lists them in the log, each friend in the valley with roughly where (riding with Marx, in the corn maze, by a Citgo, out in the valley, from their last state frame). A friend coming into the valley says so in their friends' logs. Friendships are the accounts', in D1 (`friends`, one row each way; `AccountStore.askFriend`, `friendsOf`, `unfriend`), and only usernames go on the wire (`whisper`, `friend`, `unfriend` and `friends` frames up; `whisper`, `friends` and `friend-news` down). A name no raider could have is refused in the client, since the valley closes a malformed frame. Beginning to play says how many others are in the valley, and a raider joining says their name. The text rules (`normalizeChat`, `CHAT_MAX`) are `protocol.ts`'s, and the valley nacks past 5 lines in 10 seconds. Every line in the log carries its local `HH:MM` (the valley's timestamp for a raider's line) and is inked by who said it: raiders blue, NPCs gold, the game's own lines eggshell. Older lines thin out toward the top. The log scrolls with the wheel or PageUp/PageDown (`bindings.ts` `CHAT`) while the field is open, and on hover while the pointer is free (the pack or the book open); paused, it lies under the overlay like the rest of the HUD.

Sign-in is required. The Worker's `/auth` routes (`worker/auth.ts`) sign raiders in with Google, Discord or GitHub (OAuth with PKCE; a Dev provider on dev servers only) and keep the session in httpOnly cookies: a 15-minute access token, a 30-day refresh token that carries the account's session number (`accounts.session`) and is reissued on every use; signing out moves the number on (`AccountStore.endSessions`), so every refresh token the account had, on any browser, is dead at once, and the access tokens within the quarter hour. The game is private: a new raider is held as a pending signup until they say the magic word (a secret of the Worker's, `env.ts` `magicWord`, checked there alone and never shipped to the client; a wrong one keeps the signup pending), then chooses a username (3 to 16 letters, digits or underscores, unique without regard to case). Gron, the hunched NPC beside the berry bush, changes it any time (`PUT /auth/username`) and changes the raider's character too; a `rename` frame then has the valley read the new username from D1 (never from the client), an `appearance` frame carries the new outfit, and everyone gets a `peer-updated` frame. Accounts live in D1 (`bull-valley-accounts`, `migrations/`), and so does what each account looks like: the character and guitar finish chosen at the select or at Gron are saved with `PUT /auth/look` and come back in `/auth/me`, so they follow the raider to any browser, and `/auth/me` carries the account's cosmetics too (`AccountStore.cosmeticsOf`), so the select dresses every character in them before the valley answers; the hotbar is kept the same way (`PUT /auth/hotbar`, the `accounts.hotbar` column), and so are the settings, the music and sound volumes (`PUT /auth/settings`, the `accounts.settings` column, saved a moment after a slider is let go). Nothing the game keeps lives in the browser's storage. The Worker reads the access cookie on the `/ws` upgrade and stamps the account and username on the request it forwards; the client never sends a name, and a `hello` with no stamped account is closed `unauthenticated` (4007), which sends the player back to sign in rather than into the valley alone. The client refreshes the session before every socket open. `/auth/me` always answers 200, and so does `/auth/refresh` unless it is rate limited, so a signed-out visitor is not an error.

The shared world's rules are `src/sharedworld.ts`, a pure reducer the Worker runs and `tests/unit/sharedworld.test.ts` pins. Every action first settles what was due by now (the day's turn, Marx's next changes), then acts. The world is persistent (rule 1): the first build to arrive opens it, it is kept in storage whoever comes and goes, and only a build on a newer protocol (`SharedWorld.version`) opens it afresh. Where each account last stood on foot is kept (`Valley.places`, rule 2) and comes back in the welcome (`place`), which puts the raider there. Matthew Marx's truck is the valley's (rule 3): a chain of legs stamped with server times (`marx.ts`: parked with Marx reading, donuts, the joyride, called to a whistler, the ferry home), each moved on by `settleTruck` when it is due; the valley never knows the roads, so the hello tells it where the truck parks and how long the joyride takes (`TruckRoutes`), and it reckons any other drive generously. Every client drives the same leg against the same clock (`truckplan.ts` `planLeg`, `Truck.follow`). A `board` frame puts a raider in the bed (the countdown starts with the first), a `charter` frame from the first one in names where he goes (a point inside the survey, or null for the joyride; `marx.ts` `charter`, which with no one else in the valley leaves at once, and a `charter` leg that lets the bed off there with a `dropoff` snapshot), `hop-out` takes them out, and `call` whistles (rule 5: an empty truck only, one at a time; boarding the truck you whistled is the ride home). The day turns at midnight Central (rule 6, `daily.ts`): the pickups come back, the shelves fill, the drops go. The shadowmen are the valley's too (rule 11): while anyone is placed in the valley it steps one field `CONFIG.shadowmen.tickHz` times a second (`stepShadows`, a timer that keeps the object awake until no one is left), crossing the bubble round every raider, and sends each socket the shadowmen within `despawnRadius` (and a margin) of its own raider in a `shadowmen` frame each step (`shadowmenNear`; a raider nowhere yet gets the whole field); clients draw it a beat behind the present (`shadowsync.ts`). The lookout tower by the maze's gate is out of every shadow's reach (rule 11, `lookout.ts`): it stands in the maze's frame, so the valley finds it from the `MazePlace` the hello already carries, and a raider whose last state frame puts them over its walled footprint is up on the deck, never `vulnerable` (`shadowRaiders`, `onLookout`), their beam still aimed; its deck is a registered floor and its ladder moves a raider up and down (client-only, `player.relocate`). The Book of Shadows is the account's too (rule 20, `book.ts`): the client sends a `discover` frame naming the entries it just came across (`actions.ts` `discover`, from `loop.ts` each frame and from the folk spoken to; anything found or already asked is left out), the valley writes the ones the account had not found, alone for the account (`forAccount`, `PackStore.discover`, the D1 `book` table, `newlyFound`), and sends a `book` frame naming them to every socket on the account; a frame too soon (10 in 10 seconds) or one it cannot write is nacked, and the client asks again a few seconds on. The welcome carries the whole book. Played alone, the client writes its own and nothing is kept. Geometrie, the hit points, is the account's (rule 24, `health.ts`): the valley keeps what every wounded account has lost (`Valley.wounds`), so no reconnect or second tab heals, and sizes the whole by the account's level (`Member.level`, read from D1 on the join, moved on by a `level` action when the XP crosses into a new one, so the larger whole tops the raider up; `maxFor`). The welcome carries the health. Played alone, the client keeps its own. Citgos are the account's and the portals the valley's (rule 28, `citgos.ts`, `portals.ts`): each step of the shadowmen's clock writes the Citgo any placed raider on foot stands at, by their last state frame, when it is not yet the last their account stood at (`citgoVisits`, a `visit` action, `Valley.citgos`, kept like `places` whatever the world), and sends a `citgos` frame (the `CitgoLog`) to every socket on the account, paying a Citgo found past the first its bounty (`Reduced.earn`, `ValleyDO` `pay`); the welcome carries the log. Walking through and fast travel are the client's alone, since where a raider stands is its own word (`actions.ts` `tendPortals`, `fastTravel`; `worldsync.ts` `portalNews`). Played alone, the client keeps its own log and opens its own portal on the wall clock. Geometrie is the account's too (rule 27, `buffs.ts`): the valley keeps every account not sober (`Valley.geometrie`, on its clock in seconds), dosed by each `use` once the pack has given the unit up (the reducer's `dose`), and sobered by a shattering; a `geometrie` frame (the levels at that moment) goes to every socket on the account, and the welcome carries them. The stimulated's sprint is the client's alone. Played alone, the client keeps its own and there is no one to pass to. The raider's level is the account's too (rule 22, `progression.ts`): one XP bar fed by everything, each grant named by the reducer (`Reduced.xp`, and `stepShadows`' `xp` for a burn, a spider and a burning; `XpGrant`, once per account) and worth what `progression.ts` `XP` says: a burst in the raider's beam, the Caretaker burned (the big jump), a ride with Marx that gets home with them in the bed, the day's berry, a pickup, a unit bought, a drop the valley left taken up (`Drop.spilled`; never a raider's own drop), and a collect from the Cabbage Stand, once for every whole `CONFIG.stand.xpCents` it pays out (`stand.ts` `standXp`, `XpGrant.times`), so small collects never earn more than one big one. The valley adds each account's sum in one statement (`PackStore.gainXp`, the `levels` table, no lock needed), sends an `xp` frame (the XP in all and what it gained) to every socket on the account, and, when that crosses into a new level (`CONFIG.progression`, `levelUp`), a `peer-updated` frame to everyone; the welcome carries the XP, and each `PeerWire` the level (read from D1 on the hello, never from the client). Every change comes to every client as a whole `WorldWire` snapshot with a reason; `worldsync.ts` reads it for this raider (`settledBy` whether a take, a sale or a drop was theirs, `aboard`, `seatOf`, `countdown`, `newLeg`), and `valleysync.ts` applies it. The Citgo shelves are shared too (rule 7): the valley holds every station's stock unit by unit (`WorldWire.shelves`, indexed like `world.fuelPoints`; each item a row of on-the-shelf flags, one per slot), a `buy` frame asks for the unit the buyer is looking at and the `bought` snapshot settles the race; cash is the account's wallet in D1 (`wallets`, a new account starts with $40); a buy runs alone in the valley (under its lock), which reads the wallet, refuses a sale it does not cover, and charges it and fills the pack in one transaction (`PackStore.purchase`), so a failed write never takes the cash without the item. The berry bushes are the valley's too (rule 8): the one at the spawn Citgo (bush 0) and the ring at the maze's heart (1 to 6, `CONFIG.maze.bushes`), one berry a day each per account; a `collect` frame names the bush, the `daily` reply says whether a berry came off it, and the welcome carries which bushes the account has had today's berry off. The valley remembers only the accounts that have had today's berry off each bush (keyed by `sharedworld.ts` `bushKey`), so two sockets on one account share one berry a bush. Every item a raider carries is their account's pack, in D1 (`packs`, `worker/d1packs.ts`), and the valley alone writes it (rule 10): the reducer says what goes in or out (`Reduced.pack`: a berry, a pickup, a unit bought, a drop taken up) and a `use` frame takes one out; the welcome carries the pack (everything of the account's it carries is read in one D1 batch, `PackStore.welcome`), and every change sends a `pack` frame to each socket on the account. The client applies its own change at once and takes the valley's pack as the truth when it lands; played alone, the pack starts fresh and nothing is kept. Drops are the valley's too (rule 12): a `drop` frame names the kind and how many, the valley sets it down ahead of where the raider's last state frame put them (never where the frame says, `drops.ts` `dropSpot`), and it stands only once the account's pack has given the units up (`setDown`, alone in the valley like a buy). `WorldWire.drops` carries every drop with its id, and a `take-drop` frame asks for one, first to ask wins. The oldest of what the valley itself spilled goes past `CONFIG.drops.spilledMax`; a raider's own drops lie until the day turns. The hello carries every pickup's kind, count and place (`PickupSpec`), so the valley knows what a take is worth and who is in reach of it, and where each berry bush stands. Moab trades cosmetics for what the pack holds (rule 14, `cosmetics.ts`): a `trade` frame names the offer, the valley reads the pack, refuses a trade it does not cover or a cosmetic already had, and takes the price and writes the cosmetic in one transaction (`PackStore.trade`, alone in the valley like a buy; D1 `cosmetics`). The account's cosmetics ride in the welcome and every `pack` frame, and on each `PeerWire` (read from D1 on the hello, never from the client); a trade sends everyone a `peer-updated` frame so the halo shows. Account ids never go on the wire. Shared moments are server timestamps read through `clock.ts`, so every client agrees where the truck is. A client whose `world.pickups` differ from the world's, in number or in any pickup's kind or count, is turned away (4005). Positions are not compared, so bump `PROTOCOL_VERSION` whenever placement changes: a new protocol opens the world afresh.

Bull Valley Dial-Up is the valley on a phone (rule 29): a raider may say a `dial` instead of a `hello` (`protocol.ts` `DialMessage`: the protocol and the outfit, nothing of the world), and the valley joins them with no body (`Member.dialup`, the reducer's `dial`): no world is opened for them (the welcome's `world` is null in a valley no 3D raider has opened one in), the truck pays them no mind, and their state and headlights frames are dropped, so they are never placed and no shadow reaches them. Space is collapsed for them: their locker and their Cabbage Stand answer wherever they are, world or none, Erwin deals with them and gives and rewards the rose from anywhere, and they buy off the shelves of any Citgo their account has stood at (`not-visited` otherwise). Dev only: `?valley=<id>` picks another Durable Object, so parallel e2e specs never meet; `beginRaid` in `tests/e2e/fixtures.ts` gives every page a fresh one unless a spec passes its own, and calms it (below). The Worker stamps dev-server sockets, which unlocks the `dev` frames (`hurry`, behind `__bv.hurryTruck`, brings Marx's next change to a few seconds from now; `shadowman`, behind `__bv.placeShadowman` (a spider when its third argument is true), stands one still at a spot; `caretaker`, behind `__bv.placeCaretaker`, moves the Caretaker to a spot, where it floats still until it has someone to hunt; `calm`, behind `__bv.calm`, keeps the crossing shadowmen from rushing anyone, so only the ones a spec places do; `grant`, behind `__bv.grant`, puts items in the raider's pack; `health`, behind `__bv.setHealth` (and `onLastPoint` in `tests/e2e/fixtures.ts`, so the next touch shatters), sets the account's health; `reset` opens the world afresh). ## Module map

Strict TypeScript throughout. The map (`public/data/bull-valley/`: `geo.json` and the `terrain.png` heightmap) is the game's own, committed and edited by hand; nothing fetches or regenerates it. Shapes that cross modules (world points and heights, geo.json, pack grid entries, the item types the drawing modules share) live in `src/interfaces.ts`; types one module owns stay in that module (the `Item` union is `items.ts`'s). Every module under `src/` and `worker/` has its line below: `tests/unit/modulemap.test.ts` fails on one the map does not name, and on a name with no module.

## Typography

IBM Plex Mono everywhere (`public/fonts/IBMPlexMono-*.woff2`: regular, italic, semibold and bold, the Fontsource latin subset, OFL), self-hosted; every page preloads regular, semibold and bold, and italic loads on demand; the tokens are `--bv-font` and `--bv-text-size` (1rem) in `index.html`. `boot()` awaits `fontsReady()` (and `preload.ts` `imagesReady`, the grain and the logos) before it builds any DOM, and the face is `font-display: block`, so no text ever paints in a fallback and reflows; canvas UI text (the phone, the map, peer name tags) uses `MONO` from `canvas.ts` and draws after the gate. The trade dress on packs, cans, medicine and the Citgo signs keeps its own period faces. A label that changes in place must not resize its box: the Begin button stacks every label in one grid cell (`bv-btn--stack`, `Hud.setBegin`), and the account status holds one line even when empty. Nothing ever draws a focus ring (`styles.css` turns `outline` off for every `:focus`): a focused button lifts as a hovered one does.

## Testing in a browser

- Use `channel: 'chromium'` (full Chromium in headless mode) for Playwright. The default headless shell draws WebGL in software on macOS at about 2 fps, which is too slow to drive the game. On CI there is no GPU at all, so specs take about 3 times longer; `playwright.config.ts` gives them longer timeouts when `CI` is set.
- Boot runs colophon → main menu → (account step) → character select → intro. Each title layer is black and stacked over the next, and a layer's keys arm only once it is showing: Space starts the colophon and Space skips it, the menu's buttons click (`toMenu` lands there, `toCharacterSelect` presses Die), ←/→ and Enter choose. While the pointer is free a Citgo-red edge glows round the view. The account step shows only from the menu's Create Account (the sign-in card), or straight away for a page landing from a sign-in round trip (`?auth=`, which skips the colophon) that has no account with a username yet (Choose Your Username, or the sign-in card with its error). `?skipSplash` skips the titles in dev with the saved pick; with no session it first signs in a dev raider named "Raider" and comes back.
- Specs sign in before they load the game: `signIn` in `tests/e2e/fixtures.ts` goes through the dev provider with a fresh `freshRaider()` (a tagged username, since parallel specs share one accounts database) and lands on `auth-done.html`; `beginRaid` signs in, then loads `/?valley=…` and `passTitles` drives the select. Two pages that must be two raiders need two browser contexts, since the session is a cookie. Under `--mode test` the dev server keeps its state in `.wrangler/state-test`, which the Playwright server command empties and migrates first.
- Wait for `window.__bv` before you click Begin. `boot()` sets the hook last, after the input listeners. The button reads "Click to Die" as soon as input wiring starts, before the hook is set, so its text is not a ready signal.
- To prove that a refactor changes no asset, render every Akashic asset on `main` and on the branch from the same fixed view (`__akashic.animate(false)`, then `select(id)` and `setView(35, 20)`). Compare the `.ak-stats` text and a hash of the canvas screenshot. Serve `main` from a `git archive` copy with a symlink to this repo's `node_modules`.

## E2E shards

The e2e stage takes as long as its slowest shard, so the shards should take about the same time. Playwright's `--shard` deals the tests out in file order, the same count to each, and keeps a serial describe whole; the jobs are named by number only (`E2E tests (n/total)`), never by what they hold, so nothing in `ci.yml` names a spec and a new one needs no CI change. After them `E2E shard balance` (`scripts/e2e-balance.mjs`) reads the run's own job timings, writes each shard's test step to the run summary, and warns when the slowest takes more than 1.25 times the fastest. It never fails, since runner timings jitter and a red CI run would hold back the deploy. When it warns on more than one run, even them out: split a long spec file into two (the shards cut between tests in file order, so one heavy file weighs on one shard), or add a shard (`matrix.shard` in `ci.yml`; the names and `--shard` follow it). Branch protection that requires the e2e checks names them `E2E tests (1/3)` and so on, so a change to the count changes the names it must require. The `@valley` tag (the two-page specs, which boot two games each) and `@raid` (`world.spec.ts`) are for running a group locally (`npm run test:e2e -- --grep @valley`); CI does not read them.

## Standing rules

1. The map never includes driveways, private service roads, or buildings. Edit `public/data/bull-valley/` by hand, and bump `PROTOCOL_VERSION` whenever a change moves where things are placed.
2. No GPS EXIF in any media added to the repo.
3. Landmarks are consented or public places only. Keep the consent comments in `src/landmarks.ts`.
4. The `three`/`vite` pins are deliberate: `ps1.ts` patches Three shader chunks via `onBeforeCompile`, and Three minors rename chunks. Upgrading is its own task.
5. `public/data` is intentionally minified; it is in `.prettierignore`.
6. A session of play, when the raid comes back, is a raid, not a run — in code, copy, commits, and docs. Its players are raiders.
7. Nothing stands on the raw terrain. Place and move things with `world.ground.at`, and register any new walkable surface (a floor, a deck, a lot) on the `Ground` in `world.ts` before placing on it.
8. One persistent world, one truck, one clock, shared pickups, shared shelves, shared shadowmen and their tombstones, one Caretaker, shared drops, the Citgo portals, one berry a day per account at each bush, the Citgos each account has stood at, each account's progress through the season and on the daily task, its Book of Shadows, its XP, its Cabbage Stand and its quests, every body a strike left, each account's health and geometrie, and every item in the account's pack and its locker, every cent in its wallet and every cosmetic it wears, and where each account last stood, kept by the valley. No game state is kept in the browser. A rule of the shared world belongs in `src/sharedworld.ts` (or `src/marx.ts`, for the truck, or `src/shadowstep.ts`, for the shadowmen's step) with a test, never in the Worker or in the client glue (`main.ts`, `actions.ts`, `valleysync.ts`, `loop.ts`); the client's reading of a snapshot belongs in `src/worldsync.ts`, also with a test.
9. Player-facing text lives in `COPY.toml`, never inline in code: add the entry, then call `copy('section.key')`. Anything an AI writes or rewrites there is `by = "ai"`. Never set `by = "tyler"`, and never change the text of a `"tyler"` entry unless Tyler asks. Tests and specs assert copy through `copy()`, never as literals, so editing a line never breaks a test. Out of the file: `public/auth-done.html`, the `index.html` meta tags, provider names, the Akashic page, and painted trade dress.
10. Never honor `prefers-reduced-motion`: everything that moves always moves, the same for every raider. Do not read the media query or add a still mode.
