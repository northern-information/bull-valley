# Testing in a browser

- Use `channel: 'chromium'` (full Chromium in headless mode) for Playwright. The default headless shell draws WebGL in software on macOS at about 2 fps, which is too slow to drive the game. On CI there is no GPU at all, so specs take about 3 times longer; `playwright.config.ts` gives them longer timeouts when `CI` is set.
- Boot runs colophon → epigraph → main menu → (account step) → character select → intro. Each title layer is black and stacked over the next, and a layer's keys arm only once it is showing: Space starts the colophon and Space skips it, the menu's buttons click (`toMenu` lands there, `toCharacterSelect` presses Die), ←/→ and Enter choose. While the pointer is free a Citgo-red edge glows round the view. The account step shows only from the menu's Create Account (the sign-in card), or straight away for a page landing from a sign-in round trip (`?auth=`, which skips the colophon) that has no account with a username yet (Choose Your Username, or the sign-in card with its error). `?skipSplash` skips the titles in dev with the saved pick; with no session it first signs in a dev raider named "Raider" and comes back.
- Specs sign in before they load the game: `signIn` in `tests/e2e/fixtures.ts` goes through the dev provider with a fresh `freshRaider()` (a tagged username, since parallel specs share one accounts database) and lands on `auth-done.html`; `beginRaid` signs in, then loads `/?valley=…` and `passTitles` drives the select. Two pages that must be two raiders need two browser contexts, since the session is a cookie. Under `--mode test` the dev server keeps its state in `.wrangler/state-test`, which the Playwright server command empties and migrates first.
- Every spec fails on a console error, a failed response or an uncaught page error. The `test` from `tests/e2e/fixtures.ts` watches its `page`; a spec that opens its own pages from `browser` passes each to `watchErrors` and asserts what it collected is empty (`dialup.spec.ts` does it for every page it opens, phone or desk, in `open`).
- Wait on a condition, never a fixed time. To show that something does not happen (a typed key walks nowhere), let the game step with `frames` from `fixtures.ts`; to show that nothing leaked to another raider, send a later line down the same socket and wait for that. Only a check that something lasts (a /sit outlasting a wave) waits on the clock, sized from the game's own config.
- Wait for `window.__bv` before you click Begin. `boot()` sets the hook last, after the input listeners. The button reads "Click to Die" as soon as input wiring starts, before the hook is set, so its text is not a ready signal.
- To prove that a refactor changes no asset, render every Akashic asset on `main` and on the branch from the same fixed view (`__akashic.animate(false)`, then `select(id)` and `setView(35, 20)`). Compare the `.ak-stats` text and a hash of the canvas screenshot. Serve `main` from a `git archive` copy with a symlink to this repo's `node_modules`.

## What earns a test

A test that loads the valley pays for a boot, most of a minute on CI, and two-page specs pay twice. So the suite is kept disciplined, not padded:

- One behavior, one test. Before you write one, look for a spec that already drives the same path. If one does, add your check to it instead. A test whose every check another test already makes gets cut, once its few unique checks have moved to the test that stays.
- A check that needs only a booted valley (a key list, the pause overlay, a light coming on) rides in a spec that boots anyway, near the step it belongs to. It does not get a boot of its own. The open-pack half of `controls.spec.ts` went into `inventory.spec.ts` this way.
- Variants of one mechanic share a boot. A second berry bush is a few more lines in `daily.spec.ts`, not a new test. A strike's static, respawn and body are one test in `corpses.spec.ts`.
- What is not duplication: the same feature from both apps (rule 11 asks for a 3D spec and a Dial-Up spec), the same outcome from a different cause (a fall and a shadowman both leave a body), a single-page check and its shared-world twin (`world.spec.ts` checks the glow and the pack; `sharedworld.spec.ts` checks that the other raider sees it), and each account field's own remembered-on-return check.
- Features that need the same costly setup share it, but stay separate tests. One long test makes a failure harder to place, so put them in a serial describe with the boot in `beforeAll`, one test each, as `world.spec.ts` does and as `groups.spec.ts` does for parties and crews (three raiders, booted once). A serial describe stays whole on one shard (below), so mind its weight there.
- A merged check has to stand where it lands. The view, the pointer lock and the label carry over from the step before: face the new thing (`faceSpot`) and wait on its own state, not on a label that may still say what the last one said.

## E2E shards

The e2e stage takes as long as its slowest shard, so the shards should take about the same time. Playwright's `--shard` deals the tests out in file order, the same count to each, and keeps a serial describe whole; the jobs are named by number only (`E2E tests (n/total)`), never by what they hold, so nothing in `ci.yml` names a spec and a new one needs no CI change. After them `E2E shard balance` (`scripts/e2e-balance.mjs`) reads the run's own job timings, writes each shard's test step to the run summary, and warns when the slowest takes more than 1.25 times the fastest. It never fails, since runner timings jitter and a red CI run would hold back the deploy. When it warns on more than one run, even them out: split a long spec file into two (the shards cut between tests in file order, so one heavy file weighs on one shard), or add a shard (`matrix.shard` in `ci.yml`; the names and `--shard` follow it). Branch protection that requires the e2e checks names them `E2E tests (1/3)` and so on, so a change to the count changes the names it must require. The `@valley` tag (the two-page specs, which boot two games each) and `@raid` (`world.spec.ts`) are for running a group locally (`npm run test:e2e -- --grep @valley`); CI does not read them.
